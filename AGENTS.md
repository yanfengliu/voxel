# AGENTS.md — voxel

## What this is

A browser-first, voxel-first 3D graphics and rendering toolkit for the owner's strategy and building games — voxel chunks, low-poly procedural geometry, imported assets, instanced entities, overlays, effects, and orthographic or perspective views. Stack: strict TypeScript, a Three.js WebGL2 runtime, Vitest + Playwright.

Non-goals: not a simulation engine, ECS, game-rules library, UI framework, persistence layer, asset-evolution studio, or a general-purpose Three.js replacement. A useful renderer shared by two games beats a universal abstraction that serves none well. AoE2 is the standalone sole-renderer host; City is the embedded borrowed-renderer lane; Townscaper adoption and imported-asset/extension APIs remain future work. **Do not claim a package, command, backend, benchmark, shader, mesher, adapter, or test exists until live files and executable behavior prove it.**

These non-goals describe the public renderer/runtime boundary. Private Studio authoring storage and explicit consumer fixtures may live in this repository, but renderer/core never owns durable consumer data or authoritative simulation.

Voxel's own rules — its strengthenings of the fleet constitution and the rules it adds — live in [docs/policies/local-rules.md](docs/policies/local-rules.md). They bind alongside the constitution below and win where they overlap. Do not write them into that section: it is a generated copy of `../fleet/FLEET.md` between `FLEET-CANON` markers. The fleet sync writes only inside those markers and refuses a block it did not write; the 2026-08-01 incident was caused by the retired heading-delimited sync.

## Fleet constitution

- Verify visual work visually: capture the rendered result — screenshot, frame, recording — and look at it, because a passing test says nothing about what the pixels do. Work with no visual surface runs headlessly. One framing is not a check: sweep several camera angles and zoom levels, since a defect the chosen view happens to hide is the normal case. An aggregate view — a contact sheet, grid, montage, or proof sheet — answers "is there one of each" and never "is each one right", and answers the first just as confidently when the second answer is no: inspect each item at the artifact's own native resolution, and bind the review to the digest of the bytes inspected, so regenerating the artifact strands its review instead of inheriting it. Badge's 63-source contact sheet read as cohesive while ten sources were wrong, and the lesson recurred four days after it was written down, against 48px proof sheets. Confirming the change you made is only half of it: every task ends with a sweep of the whole rendered result, looking for what is wrong rather than for what you touched. Defects hide in the parts nobody was working on, and the ones a user finds first are almost always there.
- A defect the user reports is recorded and gated, never only fixed: an entry in `docs/learning/defect-register.md` — symptom as they saw it, investigation, root cause, and how it is checked from now on — plus a check that covers the defect's whole class rather than the one instance. Unlike a lesson, the entry stays after it becomes a gate: the register is the standing list of what the gates could not see, which is where the next defect comes from.
- Commit each verified unit of change to `main` without being asked, and push. Gates pass before any commit that touches code; a dependency change re-runs the audit gate.
- A push is finished when the remote gate says so, not when the remote accepts it: watch the run to a conclusion, and read the run's status at session start before taking new work. A red remote gate is the next task — ahead of whatever was planned — because everything built on top of it is built on an unknown. The local gate and the remote gate run on different machines, and only the remote one is what a collaborator, a consumer, or a release sees. Voxel's `main` last saw a green CI run on 2026-07-24 and went five weeks without another — **131 pushes, 100 of them failing and 31 cancelled** — every one behind a green local gate, until the user reported it. The browser suite failed only on machines slower than the author's, and every machine that runs it in CI is slower than the author's.
- A repo chooses its own language and toolchain — Node, Python, and Rust all run here. Each pins its version where its own tooling reads it (`.nvmrc`, `requires-python`, `rust-toolchain.toml`) and names it in Gates, so a version mismatch is not read as a code failure. Node repos baseline at 24; an older major keeps a CI job proving it.
- Runtime model calls are authorized and already paid for — this fleet has one user, with Claude Code and Codex subscriptions — so a program here may call a model at runtime, vision included.
- The top reasoning tier is rationed: spend it only on the hardest problem, or on directing the workhorse tier that does the work — and only at maximum effort or orchestration.
- Two failed attempts at one problem escalate to the hard-problem skill: a search across deliberately different approaches, run to a result rather than to a report. Spending real budget there is authorized — a third pass at the approach that already failed is the expensive mistake. Return the working result, or the strongest proved part with its exact remaining gap.
- High-risk work — persistence/migrations, security/auth, concurrency, money, supply chain, edits that reach sibling repos — escalates to the multi-cli-review skill. That is a review you run yourself, not permission you ask the user for; nothing in this canon requires asking.
- Error messages are a product surface: audit them as a class, including paths the task did not touch. Each names what happened, which input caused it, and what would satisfy it — never a bare `Validation failed`.
- When blocked, hand over the raw artifact — screenshot, rendered page, log line, data row — as soon as the blocker is named rather than after the analysis: your description of it is filtered through the misunderstanding that caused the block, so it cannot contain what you failed to notice.
- Task-run evidence lives only under ignored paths and is deleted once nothing active needs it; it enters Git only when review promotes it into a repository input — a fixture, golden, snapshot, or contract. Tracked docs keep conclusions and provenance only. Blob ceilings for anything promoted: over 256 KiB needs a stated reason, over 512 KiB binary or 1 MiB of anything never enters ordinary Git, and an asset store or LFS needs the user's approval.
- Write prose one line per paragraph (no hard wrapping).
- Keep a devlog: one short dated line per behaviour-changing session in `docs/devlog/summary.md`, newest first, and a section in `docs/devlog/detailed/` for anything a later session could trip over — what was believed and proved false, what a reviewer caught that the author missed, what number moved and from what. It is history, not status. Both shapes are in `../fleet/docs/devlog-template.md`.
- A lesson is prose only until it is a gate. It lands the session it is learned in `docs/learning/lessons.md` — read at session start — anchored to a measurement, commit, or test id, and naming the gate that will retire it: a test, a lint rule, a schema check, a fixed command. That file is a queue: an entry is deleted in the commit landing its gate, and a gate counts only once it has been made to go red by reintroducing the defect. An entry that can name no gate is not a lesson — fleet-wide knowledge is staged in `canon-candidates.md` for this constitution, repo-only knowledge goes to `docs/policies/local-rules.md`, and the rest is folklore and is dropped. An index that only grows is a list of things that failed to graduate: aoe2's reached 84 entries, none naming a gate. An index already holding ungated entries is emptied entry by entry as each one's area is next touched, not kept as a standing exception. Shape: `../fleet/docs/lessons-template.md`.
- A green gate proves less than it looks like. Every gate is bounded by something — a seed set, a tick window, a resolution, a fixture that ends early, an include list, a shared flag any one case can satisfy — and proves nothing past that bound, so name the bound in the gate's own header and pin every input that reproduces the defect, not just the one you thought of. Past its bound a gate does not merely miss the defect — it can measure a different phenomenon entirely and report it just as confidently: aoe2's stone-mining window opened at tick 11,000 on a fixture that resolves by conquest at 11,442, so it was reading a decided match, and a finished match and a deadlocked one are pixel-identical. A gate that cannot tell "passed" from "did not run" reports the second as the first, and a check built from the same symbol as the thing it checks proves only that the code agrees with itself. Retiring 356 lessons across 13 repos found **43 whose evidence named a live, passing test that did not catch the defect**: an 800-decision rollout window hid a divergence that starts at 3,000, a Rust-side struct pin stayed green while the WGSL side it mirrors gained a field, and `replaceFootprintOwner(…, undefined)` passed all 873 tests.
- A command's exit status is a claim about the command, not about the work: a pipeline exits with its last stage's status, so `npm run x | tail` reports tail's success over any failure; `git add` fails all-or-nothing while the `commit` after it still succeeds and ships a message that lies about its contents; and a tool reporting that it applied a fix reports a no-op identically to a refusal — read the artifact it should have changed. Red deserves the same suspicion as green: a non-zero exit is equally a claim about the command, and a missing dev dependency, an unresolvable binary or a wrong working directory fails identically to a broken product — aoe2's `playtest:corpus` went red on a merge because `tsx` was gone from `node_modules`, not because the code was wrong. A blocker you inherited is the same kind of claim: retest it before repeating it, because its whole effect is to stop work.
- Every unit of work gets an independent harsh critic before it is called done — a subagent that did not do the work, given the diff, the claim, and the measurement, and asked to find why the measurement does not support the claim. Hard problems get several with deliberately different lenses. This is not a courtesy pass: every multi-lane review run so far has found a defect the author missed, including three in a cache its author had already gated and mutation-tested.
- Verify the instrument before trusting the measurement, because a critic is a backstop and not the first line. Confirm the flag took effect, the denominator is the population you meant, the control reproduces, and the claim you are relying on is still true rather than remembered. A whole session's conclusions were built on labels chosen with knowledge of the future, agreement quoted over a population that was 99.8% forced no-ops, a `--eval-episodes` flag silently ignored so every checkpoint was picked by a five-sample lottery, and a review lane declared unavailable from a three-week-old memory that was wrong. Each was one command away from being caught.

- A standing loop sources its next task by running the artifact the way its user does — the default entry point, the real configuration — never by reading code for something to improve. A repo with no runnable entry point has no standing loop.
- This harness compacts context mid-task: a compaction is a harness event, not a task boundary, and never a reason to wrap up or hand off to a fresh session.

- Delegation is paid for in tokens: a subagent re-reads the canon and its source files from scratch, and its own critics and gate runs multiply that, so it costs a multiple of doing the same work in the parent. Budget agents like a rationed resource, not like parallelism that is free — a session that keeps fanning out past its ceiling trips the limit and kills every agent's in-flight work mid-task, which is how a dozen agents cost a day of the top tier on 2026-09-02. What a delegation actually costs is measured, never remembered: a figure written here is evidence about a model and a codebase at one moment, and both move.
- Run **one agent at a time** by default; two only when both are long, genuinely independent, and touch different files. Concurrency does not merely multiply tokens: agents sharing a machine fight over the dev server, the sibling build and the CPU, and their retries cost more than the parallelism saves — three merges aborted on a shared-dist race in one session, and two agents' `git stash` calls crossed and deleted each other's work. A checkout another session is live in is not yours to run destructive git in: `git commit` without `-a` still commits whatever that session had staged, and `git reset --soft` restores HEAD and the index byte-perfectly while deleting `.git/MERGE_HEAD` — so a merge in progress loses its second parent, `git merge --abort` stops working, and the next commit records the content with the branch never marked merged. Stage by pathspec, and when you have already disturbed someone's checkout, say which invariant you broke rather than that the state is restored.
- Delegate only what needs a **fresh context window**: an independent critic, a multi-file implementation with its own TDD loop, a search across deliberately different approaches. Everything else stays in the parent — merges, gate runs, version bumps, changelog edits, reading a file, running a script. An agent spun up to run a command costs a thousand times what the command costs.
- Give an agent the **answer, not the search**. Every fact the parent already knows — file paths and line numbers, the root cause, the measured numbers, the version to use, what is already on disk — goes in the brief. An agent left to rediscover a root cause pays for the whole investigation a second time.
- A killed agent's **worktree survives**; its transcript does not. Relaunch into the existing worktree with a brief that names what is already there and what remains, so the work is finished rather than redone.
- The critic stays: every multi-lane review so far found a defect the author missed, and one that blocked a shipped release. But one critic per unit of work, given the diff and the claim — a lane per dimension is for high-risk work only.
- Treat the quota like a gate: past roughly **1M agent tokens in a session**, stop fanning out and finish what is already open.

- Steering compounds: a direction that outlives the immediate task lands that same session — `../fleet/FLEET.md` if fleet-wide, else this repo's `docs/policies/local-rules.md` — and you say where it went.
- Reviewer model pins live only in `../fleet/docs/skills/multi-cli-review.md`; a model a product itself calls is pinned in the repo that calls it. Never hardcode a model ID anywhere else.

## Gates

Toolchain: Node 24, pinned in `.nvmrc`. CI runs the complete `npm run verify` — browser suite included — on Node 24 across Linux and Windows, and a portable subset (unit tests, typecheck, lint, build, public API, core-only package) on Node 22, so the older major a consumer may still be on stays proven without the baseline's own gate being the one that never runs.

Authoritative commands live in `package.json`. For non-trivial work, run the smallest relevant checks while iterating, obtain adversarial review, fix its findings, then run one final **`npm run verify`** (build · test · typecheck · lint · compatibility · public-API · core-only / mesh-worker / three package checks · supply-chain · browser) before declaring implementation complete. Any later code change requires another full `npm run verify`; a later doc-only change requires the applicable doc checks. Doc-only work must at least pass diff review, link/path checks, Markdown-fence and whitespace checks, and literal intent/forbidden-content searches for user-steered wording; consolidate one coherent doc-only correction before pushing. Never invent a successful command result.

Renderer changes verify to the risk: deterministic unit/property tests (storage, meshing, bounds, seams, revisions, picking); browser tests against the served app (resize, input, capture, context loss, teardown); fixed camera/viewport/DPR reference scenes with before/after screenshots; structured render metrics (draw calls, triangles, GPU resource counts, dropped stale jobs); repeated rebuild/teardown showing stable resource counts; measured performance on named scenes with hardware/browser recorded.

Visual work is never complete until the rendered result has been visually inspected at the intended camera, viewport, and device scale, plus at least one adversarial angle or state appropriate to the risk. Automated pixel comparisons preserve known output but do not replace first-hand inspection; record what was inspected and fix visible discrepancies before declaring completion. (Established 2026-07-26.)

A local green run is not evidence about CI. The browser lane fails on hardware slower than this workstation and on nothing else, so every browser budget is sized from a measurement of the test it guards — the suite default in `playwright.config.ts` from the slowest test that uses it, plus the allowance `tests/testing/test-timeout.ts` charges for a machine that is not the author's, plus a measured margin for what a slow host does to the work; a test heavier than that declares its own `test.setTimeout()` with its measurement beside it. There is deliberately no `process.env.CI` branch, because a budget only CI executes is the same defect again. `tests/testing/browser-timeout-headroom.ts` fails a passing run whose slowest test has spent over 75% of its budget, so a test is reported while it is still merely close — which is where it is visible, since the test that took CI down had been running at 88% of its budget on this machine. Read the remote run's result rather than assuming it matches the local one. (Established 2026-08-28, after five weeks of red CI behind green local gates; see [docs/learning/defect-register.md](docs/learning/defect-register.md).)

## Invariants & boundaries

- The game simulation is authoritative; renderer state, scenes, meshes, materials, textures, acceleration structures, captures, and metrics are disposable derived artifacts.
- Public render inputs are bounded, structured-clone-safe data — opaque never-reused render keys or explicit local-ID generations, plus schema/epoch/revision — with no callbacks, DOM objects, Three.js objects, or consumer world types.
- Portable core, voxel storage, meshing, and voxel/heightfield ray-query code must not import Three.js or touch the DOM. The Three.js adapter owns all GPU and browser integration (`THREE.Raycaster` included).
- Consumer adapters translate game snapshots/deltas into engine inputs; roads, zones, AoE units, Townscaper facades, and production simulation components stay in their game repositories. Bounded explicit consumer fixtures may live here as evidence, but never become renderer/core authority.
- Promote scene-enabling mechanisms into Voxel only as bounded, game-neutral capabilities reusable by downstream games; keep each scene's choreography, scripted trajectories, physics or simulation, causal event rules, and game semantics in Studio or consumer fixtures or game-owned adapters, with the renderer observing versioned plain-data state it is handed each frame.
- Scenes simulate live (owner rule, 2026-07-30): every scene computes its motion in real time, at frame rate, in the browser. This is the whole point of having scenes — they exist to exercise the runtime a real-time game will actually use, and a scene that replays baked poses tests the decoder instead. A pre-recorded trace is never a scene's source of truth; it is at most a determinism fixture a test compares against, and it must never be what the studio plays back for the owner. Every scene is now live: Machine Works, Riverfall, Windmill, and the chain were the four still recorded when this rule landed, and all four were converted — `tools/studio/live-physics-profiles.ts` registers a live profile for each, and `tools/studio/catalog.test.ts` refuses a recorded shelf scene. No new scene may be added on the recorded lane. Judge a live scene by what the renderer sustains: frame budget, draw calls, and resource counts under real simulation, inspected on screen rather than measured from a file.
- Everything solves at 60 Hz (owner rule, 2026-07-31): one lane constant, `LIVE_TIMESTEP_SECONDS_V1`, and every solver lane derives its step from it rather than spelling a literal. 240 Hz was the owner's monitor refresh rate, never a target — no consumer runs that high, and a rate nobody ships is a rate nothing is really tested at. A lane that cannot yet meet it says so where its constant is declared, with the measurement that blocks it, and is delivery work rather than a permanent exception. `tools/studio/solver-rate.test.ts` fails on any lane that drifts off the shared constant.
- Coordinate, unit, color-space, alpha, and transform conventions are explicit at the boundary — never an implicit axis swap, scale, or color conversion.
- Input typed arrays are borrowed and copied on ordinary ingest; only an explicitly named ownership-taking API detaches adapter-owned transfer buffers, and simulation-owned memory is never transferred.
- Meshing is deterministic for identical canonical inputs; async jobs carry world epoch, resource incarnation, source revision, and dependency revisions so stale worker results never overwrite newer state.
- Accepted state is tracked separately from presented state: mesh swaps at frame boundaries, picking reads the same presented data as the canvas, capture waits for or reports incomplete presentation. Committed `pickPresented` requires a world whose descriptor carries `chunkProfile` and whose runtime enables `voxelWorkers`; other paths report typed unavailable outcomes (`no-presented-frame`, lost/restoring/failed/disposed).
- GPU ownership is explicit — every renderer, control, listener, frame callback, geometry, material, texture, render target, cache entry, extension scope, and worker has an idempotent disposal path; context loss/restore follows an explicit state machine.
- Time is injected through the frame context; deterministic paths never read `Date.now()`/`performance.now()` directly (tests drive a manual clock).
- Physics flaws are fixed as universal law (owner rule, 2026-07-31): when a simulation behaves impossibly, the repair is a law of this voxel universe, never a patch to the scene that exposed it. State each law as what holds, not what is banned: surfaces resist sliding, rolling contact resists the roll, a bearing resists its shaft, air resists both travel and spin, a collision returns less than it receives, a passive machine only ever spends the energy it started with, and Newton's three laws hold and are measured rather than assumed. Laws live in one module, published as `voxel/physics`, and are applied where rigid bodies are created — every solver lane in this repository, the consumer fixtures included — so no scene here can opt out by forgetting to opt in. A downstream game keeps its own solver and does not inherit them automatically; it borrows them by calling `applyPhysicsLawsToBodyV1` at its own body-creation site, which is the whole reason the module ships free of Three.js, Rapier, and the DOM. Content may tune a law per material and must state the measured effect; content may never exempt itself, and a law that a body can escape by declaring nothing is not a law. Prove each with a counter-run that fails when the law is overridden away, and prove no content escapes with a test that walks every material and every body. When a new law shortens a throw or moves a landing point, move the scenery to follow the physics — bending a machine to protect a number is how a workaround becomes furniture. Retire the scenery that existed only to compensate for the missing law.
- A mechanism declares which of its parts may touch (2026-07-31, commit `be30dd8`). A live physics profile carries a `contactPolicy` naming the permitted body pairs, and every collider not named in one is inert for that mechanism — which is how a shaft passes through the housing that holds it and a cam slips off its follower instead of gripping it. The everything-meets-everything default stays for a chain or a heap, which need it. Declaring the pairs is not a simplification of the mechanism, it is the mechanism, so a contact a machine relies on is named rather than discovered by the solver; `windmill-scene.test.ts` pins that profile's two.
- Placed things are solid (owner rule, 2026-07-30): no two placements may co-exist in the same space — recorded poses included — and no two same-facing surfaces may lie on one rendered plane, because coincident same-facing area is what fights for visibility and always means shared volume. Flush back-to-back contact is the only legal coincidence; recorded physics may dent a contact only by its numerical slop; where two grains must nearly meet, keep them apart by an authored clearance off every involved lattice (the Machine Works still-settle is the pattern). Enforce at content boundaries — `sceneOverlapsV1`, `sceneSurfaceFightsV1`, the studio's live conflict line, and the fixtures' generation-time penetration budgets — and fix geometry at its source; never hide a fight with renderer depth tricks.
- Never create one scene object or draw call per voxel at production scale — cull hidden faces, mesh by chunk/region, instance repeats, and make overflow policy explicit.
- Keep `three` an optional peer (`peerDependenciesMeta`), externalized from the build, aligned to one tested release, and deduped for linked Vite consumers — verify a single runtime Three.js instance. WebGL2 via Three.js `WebGLRenderer` is the first production backend; keep the data plane portable but build no speculative backend abstraction before a measured need.
- Public API compatibility holds unless the task authorizes a versioned breaking change; schema changes require explicit versioning and migration guidance. Files stay normally under 500 lines, and no new hand-authored file may exceed 1000. Treat existing files above 500 lines as ratchets: do not materially grow them without an explicit reason and a bounded extraction plan recorded with the change.
- Do not modify a sibling repo (`../city`, `../townscaper`, `../aoe2`) unless the task explicitly includes it — consumer code is evidence for a contract, not code that belongs here.

## Conventions

- Session start: read `README.md` and `docs/design/spec.md` before substantial work, on top of the lessons index the canon already sends you to; inspect the relevant consumer path in `../city`, `../townscaper`, or `../aoe2` before changing a public contract intended for it.
- Keep `README.md` truthful about implemented status and `docs/design/spec.md` aligned with architectural contracts and delivery gates; update consumer integration notes when a public API or supported Three.js range changes.
- Keep `README.md` capability-oriented: do not add Studio scene descriptions, inventories, status, provenance, metrics, or per-scene links there.
- Record why an authored decision exists as typed graph edges, not prose: a `beneficiary` sentence cannot be traversed, so nothing can check that a chain of reasons terminates or that a stated need is served. Project a system's purpose ledger onto [the purpose graph](docs/design/purpose-graph.md) and let the kernel find orphans, justification cycles, unserved needs, and contradicted system boundaries. Keep the ledger prose as the single source of truth and add only edges and evidence. (Established 2026-07-28, after translating Windmill's prose exposed two mutually justifying contact pairs.)
- Creative model/recipe work is judged by contrast coverage, not item count: palette or seed swaps alone do not count as distinct; a promoted model must differ from its nearest catalog neighbors on at least two independent axes among topology/negative space, multi-view silhouette/massing, scale/proportion, construction/part grammar, material rhythm, or supported motion. Generate deterministic contrast batches, inspect fixed multi-view contact sheets plus structural fingerprints, reject near-duplicates, and extract a reusable part only after a second real use; keep consumer-specific art in its game repository and do not turn Voxel into an asset-evolution system. (Established 2026-07-26.)
- Record source, version, license, and redistribution requirements for imported code, shaders, textures, models, and sample assets — permission to view a sibling asset does not make it appropriate for a reusable package.
- Temporary captures, traces, benchmark output, and renderer dumps belong in ignored output directories; commit only durable fixtures, concise evidence, and documentation useful to a future maintainer.
