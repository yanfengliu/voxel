# Devlog — 2026-08-31

The owner rejected the gap between numerical authority and what the case study actually showed: “I see no animation for rain or wind, and the soil looks completely flat and therefore fake.” The repair keeps the simulation authoritative, but gives each environmental claim bounded, inspectable voxel evidence.

## A ledger update is not visible rain

The rain command already queued an authoritative `0.40 L` pulse, and later water-balance checks proved where it went. Before this repair the frame between those events contained no rain at all. Wind had the opposite half of the problem: its `3–6 m/s` mechanics forcing changed organ directions, but without a moving reference those small voxel-pose changes were difficult to distinguish from quantization or a still frame.

One seventh instance batch now reuses the exact tissue cube geometry under a transparent unlit weather material. Thirty-six deterministic sites emit six-cube falling trails for `78` host ticks, and an active breeze advects those trails in the same normalized direction exported by oak mechanics. The impact phase retains an exact cube on each surviving shared terrain contact and selects varied bounded direction counts, radii, heights and trail lengths for the short outward and upward rebounds that remain for `24` ticks before every rain cube expires. Eighteen short airflow packets advance in that shared mechanics direction. Their positions are representative evidence only: the rainfall ledger and eight soil cells still own water, while wind speed and organ pose still own mechanics.

The first integrated browser sequence revealed that merely drawing the cue beside the old command was causally false: accelerated growth could process the full pulse about three host ticks after the click while the trail was still near the top of its 78-tick fall, and wind inspection could let the cue expire before biological soil time progressed at all. The host now leaves cumulative water sources and soil storage unchanged through the falling phase. Every final-fall cube bottom remains strictly above terrain; first exact retained-terrain contact on the impact frame issues the authoritative pulse, after which the consumer's own soil cadence processes it during impact. Wind mode may honestly retain it as pending until biological time resumes.

The first airflow implementation multiplied elapsed ticks by the gust speed at the end of the interval. A critic measured the resulting phase error: ticks `0..15` travelled `1.3125 m` instead of the per-sample `1.225 m`, about seven percent high. Mechanics now exports one speed function and one per-`60 Hz` interval integral; both organ forcing and presentation consume those functions. The browser host accumulates each active sample rather than reconstructing travel from the endpoint. A later critic found that falling-rain drift still converted the instantaneous gust speed into a total offset, so a weakening gust could pull a trail backward. Each rain event now records integrated wind travel at launch, maps only the nondecreasing event-travel difference into at most eight display cells and holds that displacement when airflow stops. An exhaustive counter-run covers all 120 gust launch phases and all 78 falling ages.

The same review found exact day-240 impact coordinates shared with fallen-litter cubes. Weather now treats living tissue, litter and fine soil-contact refill as one placed-scene occupancy set; every impact age in both whole and cutaway views is checked against all non-weather batches.

Pause is an actual control, not a screenshot trick. A rain command issued while paused records the pending cue but a one-hundred-millisecond control interval leaves host tick, rain phase, accepted frame and infiltration unchanged. Resuming or an explicit deterministic harness advance progresses the cue and the contact-triggered authoritative soil-process pulse. A separate ordinary unpaused `requestAnimationFrame` gate proves that falling rain and combined breeze cues move without harness ticks. A weather-only render frame hits the tissue, soil and litter projection caches and emits exactly one sparse operation for the weather batch.

## Moving weather exposed canonical chunk-index lineage

The root-cutaway rain sequence produced a valid state order the previous still scene had not exercised: a displayed chunk, an accepted chunk change still waiting on a worker, repeated sparse weather-batch targets that superseded presentation, and then another soil chunk change. Canonical state accepted the sequence, but the atomic pipeline constructed the final chunk delta from the last *presented* chunk index even though the delta's base was the last canonically committed candidate, which need not have reached either a worker or the canvas.

The pipeline now records only the lightweight `{candidate, index}` of the last canonically committed target when the runtime crosses its activation boundary. That boundary is after canonical commit, so the lineage is retained even if scheduler revalidation then rejects or blocks target activation; accepted state stands and the next frame must derive from that accepted predecessor. This does not authorize an unpresented mesh for reuse: reusable meshes still come only from the stager's displayed bundle, so each stale displayed chunk in the regression sequence schedules one fresh worker job instead of retaining the prior plan's groups, jobs and batch pages.

The first counter-run presents the initial chunk, commits an unpresented chunk update, supersedes it with two batch-only patches and requires a second chunk update to reserve normally with one mesh job. Full snapshots now pass their explicit canonical base into the same selection: removing and recreating one chunk advances its slot generation through the accepted predecessor instead of resetting an ABA key, while a changed profile in a new epoch starts at fresh generation one and a same-epoch profile mutation remains illegal. Candidate and index lineage is scoped to one world and epoch.

A reviewer then found that recovery treated the existence of *any* active target as success, so a rejected revision-three activation could leave a mismatched revision-two target active and idle forever. Recovery now accepts an active target only when world, epoch and revision all match the pending canonical candidate. Scheduler drift that makes every replacement stale is retried at the existing bound and fails on attempt eight with the actual `reservation rejected: stale-target` outcome rather than reporting only the outer reservation shape.

Two reentrancy windows were separate defects. Coordinator admission is now fenced for every presentation-lease state after `prepared` until settlement clears the current record, including callbacks that reenter after a lease is already `committed` or `aborted`. Scene-root detach and attach themselves emit synchronous `removed` and `added` callbacks, so the lease now enters `swapping` before scheduler commit and root mounting begin; reentrant acceptance from either callback receives `presentation-in-flight`, and the incoming frame remains the one that commits.

Those same synchronous root callbacks exposed two different owner actions that an admission fence cannot solve. A callback that calls `runtime.dispose()` now records deferred disposal until the outer atomic frame aborts or settles and its operation unwinds, then drains teardown synchronously with the root empty, the runtime disposed without a failure and a repeated dispose as a no-op. The standalone frame returns quietly. Embedded-host preparation detects the ended generation after activation, aborts and settles that target, and rejects with the existing `three.frame-ticket.late` code before issuing a ticket; commit uses the same existing code after consuming its ticket; abort completes its rollback before teardown. A callback that calls standalone `runtime.frame()` instead receives a clear error before any nested draw, so a transient empty or incoming scene cannot be stamped as the prior presented revision without widening an exported protocol-code union.

The first implementation did widen both exported result unions, and the public-API snapshot rejected it. The final contract retains the existing unavailable reasons and protocol codes; `api/public-api.json` changes only because the generated class declaration records the compatible private disposal-owner extraction.

`runtimeAtomicFrame.ts` grows from `558` to `590` physical lines in this repair because the post-callback lifecycle decisions must remain beside the irreversible `RevisionAtomicFrameCommitInternal` phase and be shared by standalone and embedded host paths; splitting those decisions during the incident repair would duplicate the transaction law being fixed. This is a bounded exception, not a new baseline for growth: before that file gains another behavior, extract recovery keying, retry accounting and `ensureTargetInternal` into a Three-free `RuntimeAtomicRecoveryInternal`, move its counter-runs with it, and bring the coordinator below `500` lines without changing the frame-operation surface.
